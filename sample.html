Stop building one giant AI agent.

An excerpt from Build Your Agentic AI OS, the approval-first VS Code guide from ThroneStack.

The phrase Main Brain sounds like one model should know everything and control everything. That design becomes fragile quickly. It produces a large prompt, unclear authority, unpredictable tool use, and no clean place to diagnose a failure.

A better Main Brain is a small control plane. It should:

  1. understand the user’s request
  2. classify the work
  3. select an allowed workflow or specialist
  4. assemble only the context that workflow needs
  5. request approval when a boundary is reached
  6. record the decision and result

The specialist does the domain work. The Main Brain handles routing and policy.

A practical mental model

Think of the system as a well-run studio:

  • Front desk: accepts and clarifies requests
  • Dispatcher: routes work and checks policy
  • Specialists: research, draft, analyze, or implement
  • Approver: a human decides whether a consequential output proceeds
  • Archivist: records sources, decisions, and durable facts
  • Auditor: reports failures and unexpected behavior

One model may perform several of these roles during an early prototype, but the roles should still be explicit in code and data. That separation lets you change models later without redesigning the entire system.

Exercise: choose one workflow

Do not begin with “run my business.” Complete this sentence instead:

When __________ happens, the system should collect __________, prepare __________, ask me to approve __________, and record __________.

Start with one workflow that has a visible beginning, a human decision, and a recorded ending. If you cannot describe it in one sentence, make it smaller.
